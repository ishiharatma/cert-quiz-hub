# quiz-data.json スキーマ・品質ルール

## JSONスキーマ

`quiz-data.json` はオブジェクトの配列。各オブジェクトの必須フィールド：

```json
{
  "question_number": 1,
  "question": "問題文（最も適切なものを一つ選べ。で終わること）",
  "choices": [
    "選択肢A",
    "選択肢B",
    "選択肢C",
    "選択肢D"
  ],
  "correct_answer": "正解の選択肢テキスト（choicesのいずれかと完全一致）",
  "correct_answer_index": 0,
  "explanation": "解説文（なぜ正解か、他の選択肢がなぜ不正解かを含む）",
  "major_category": "大カテゴリ名",
  "category": "1.1 サブカテゴリ名"
}
```

## フィールド仕様

| フィールド | 型 | ルール |
|---|---|---|
| `question_number` | number | 1始まりの通し番号。連番で重複なし |
| `question` | string | 「〜として、最も適切なものを一つ選べ。」で終わること |
| `choices` | string[] | 必ず4択。順番はランダムに見えるよう配置 |
| `correct_answer` | string | `choices` のいずれかと **完全一致** |
| `correct_answer_index` | number | 0〜3。セット全体で均等分布 |
| `explanation` | string | 正解の根拠＋不正解の理由を含む。100〜300字程度 |
| `major_category` | string | 試験シラバスの大項目名 |
| `category` | string | `"1.1 〇〇"` 形式のサブカテゴリ |

---

## 選択肢の品質ルール（最重要）

### ルール1: 文量の均等化

各選択肢の文字数は **セット内で最短の±50%以内** に収める。
正解だけが突出して長い・短いことは絶対に禁止。

```
悪い例:
  A: "ニューラルネットワーク"  ← 短すぎ
  B: "多層のニューラルネットワークを用いて複雑なパターンを自動的に..." ← 長すぎ（正解）
  C: "報酬シグナルを最大化するよう環境との..."
  D: "正解ラベルを一切使用せずデータ内部の..."

良い例:
  A: "多層ニューラルネットワークによる特徴の自動抽出を行う手法"
  B: "報酬シグナルを手がかりに試行錯誤を繰り返す学習手法"
  C: "正解ラベルなしでデータ構造を自律的に発見する手法"
  D: "専門家が特徴量を手動で設計する従来型の機械学習手法"
```

### ルール2: 構造の統一

全選択肢の文体・構造を揃える。

- 「〜する手法」「〜のこと」「〜を指す」など語尾を統一
- 括弧・専門用語の使用頻度を均等にする
- 1つだけ体言止め、他は文末ありという混在は禁止

### ルール3: 誤答の質

誤答は **一部だけ間違っている** もっともらしい内容にする。

- 完全にでたらめな内容は不可（「すべて同じである」「存在しない」等）
- 関連する別の技術・概念を使って紛らわしくする
- 正解と同じ話題・レベルの記述にする

### ルール4: 正解インデックスの分布

問題を追加するたびに `correct_answer_index` の分布を確認し、
0・1・2・3 が均等になるよう調整する（±2問以内の差）。

### ルール5: 問題文との関係

問題文のキーワードが **そのまま正解の選択肢だけに含まれる** のは禁止。
問題文から正解が自明にならないよう、全選択肢に問題文の語彙を適度に散りばめる。

### ルール6: 解説文の要件

- 正解の根拠を明確に述べる
- 代表的な誤答（紛らわしいもの）がなぜ不正解かを1〜2件説明する
- 外部知識なしに読めること（定義から説明する）

---

## 生成時のチェックリスト

問題を1件生成・追加するたびに以下を確認：

- [ ] 選択肢4件の文字数が最短の150%以内に収まっているか
- [ ] 語尾・文体が全選択肢で統一されているか
- [ ] 誤答がもっともらしい内容か（明らかな誤りではないか）
- [ ] `correct_answer` が `choices` のいずれかと完全一致するか
- [ ] `correct_answer_index` が正しい位置を指しているか
- [ ] `question_number` が連番になっているか
- [ ] `explanation` に正解の根拠と代表的な誤答の説明があるか
- [ ] `correct_answer_index` の全体分布が偏っていないか
